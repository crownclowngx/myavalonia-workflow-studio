# Workflow Action G3.1：协议一致性与静态引用安全

## 目标与边界

G3.1 在不引入 AIFLOW、脚本引擎、事件总线或通用工作流框架的前提下，硬切 Workflow Definition v2，
消除 Host/Studio Schema 漂移，并把可证明的引用错误提前到运行前。插件版本为 `1.1.0`，manifest 要求
SDK `[3.2.0, 4.0.0)`；Core/UI/Workflow 使用精确版本 `3.2.0`、`3.2.0`、`1.0.0`。

本阶段不修改或发布 Build、Templates、Host 产品与其他业务插件，不运行 Windows CI、Windows Smoke、
Host Release Acceptance 或 Host 产品发布门禁。

## 实施结果

- Codec 只接受 v2 的 `schemaVersion`、Contract/Presentation revision、summary 与 steps；v1 保留历史文档但拒绝导入。
- 验证器使用共享 Workflow SDK 的 Rune、Int64/decimal、Schema 路径与保守可赋值算法。
- 对象引用每一段必须 required；数组段必须为非负整数并由 minItems 保证。
- Secret 用当前会话真实字符串值校验；ForEach 输出形状合成为 Action 输出数组。
- Contract 漂移阻止执行；Presentation 漂移只产生 `catalog.presentation-stale` Warning。
- 引用失败转换为 `WorkflowRunFailure`，调用前失败不生成虚假 invocation entry。
- `MainDocument` 拆为 `WorkflowEditorCoordinator` 与 `WorkflowRunSession`，自身只保留生命周期、状态和命令映射。

## 专项门禁

入口为 `scripts/Test-WorkflowStudioG3.1.ps1`。候选阶段从隔离 feed 完成 locked restore、Release
零警告构建、测试、覆盖率、Standalone 4 次 Fake Action/1 次 Run 释放、Secret canary、两次确定性 ZIP
及候选 Host 启动。发布 SDK 后，使用全新 NuGet 缓存和纯公开源重复同一流程。

整体行/分支覆盖率下限为 85%/75%，Codec、DefinitionValidator、ReferenceResolver、Runner 与 Catalog
等协议关键类行覆盖率下限为 90%。所有测试必须无失败、无跳过。

## 发布安全

聊天、日志或历史中出现过的 NuGet 凭据一律视为暴露，不得使用。发布只能接受重新创建的短期、最小
包范围 Token，并通过临时进程环境或隐藏输入传递；完成后立即撤销。NuGet 版本不可覆盖，任一版本已存在
或任一上传失败都必须停止后续上传并记录部分状态，不重打同版本。
